# 기상청 날씨 연동 설정 안내

## 현재 확인된 범위

현재 서버는 배포되어 있으며, 사용자가 Codespaces 웹 미리보기에서 실제 날씨 표시 성공을 확인했습니다.
이번 안내 파일 정리에서는 실제 API 호출이나 배포를 다시 수행하지 않았습니다.
단위 테스트의 API 응답은 모두 합성 fixture이고 기상청 실측 응답 캡처가 아닙니다.
API 이용 신청·승인 후 해당 서비스 최신 활용가이드 및 실제 응답으로 필드와 제공 시각을 다시 확인해야 합니다.

공식 서비스: https://www.data.go.kr/data/15084084/openapi.do
기상청 단기예보 조회서비스 `VilageFcstInfoService_2.0`:
- `getUltraSrtNcst`: `T1H` 관측 기온, `PTY` 관측 강수 형태.
- `getUltraSrtFcst`: `SKY` 예보 하늘 상태, `PTY` 예보 강수, `LGT` 예보 낙뢰 지표.
- LGT의 정상 숫자가 0보다 크면 낙뢰 가능성 배경/안내를 사용합니다. 강도 등급이나 실시간 낙뢰 관측으로 해석하지 않습니다.
- LGT 누락은 null(미확인)이며 0(없음)으로 바꾸지 않습니다. 필드가 제공되지 않는 응답에서는 thunder를 임의 생성하지 않습니다.
- SKY=1은 맑음, 3/4는 흐림. PTY=1/2/5/6은 비 계열(2/6은 혼합 강수), 3/7은 눈 계열입니다.
- 낙뢰 예보가 있으면 thunder를 우선 표시하고 안내에 반드시 '예보'라고 씁니다.
- 그 외 비/눈 배경은 현재 관측 PTY로 판단합니다. 예보 PTY는 별도 보관하되 지금 비가 온다는 근거로 쓰지 않습니다.
- SKY가 현재 관측값인 것처럼 표시하지 않습니다. 홈 출처 영역에 관측 시각, 예보 유효 시각, 예보 발표 시각을 KST로 표시합니다.

## 파일과 데이터 흐름

`expo-location` → 위치 권한/좌표 → `shared/location.ts` → `shared/kma.ts` DFS 격자
→ HTTPS `/weather?x=60&y=127` → Cloudflare Worker → singleton Durable Object
→ 서버에만 보관한 기상청 키로 초단기실황+초단기예보 조회 → 정규화한 값만 앱에 반환.

- 서버 코드: `server/worker.ts`, `server/wrangler.jsonc`.
- 서버와 앱 공통 순수 로직: `shared/kma.ts`, `shared/mode.ts`, `shared/location.ts`.
- 앱 네트워크/위치/상태: `src/features/weather/api.ts`, `location.ts`, `useWeather.ts`.
- 서버 코드는 앱에서 import하지 않으며 서버 전용 키를 Expo 번들에 넣지 않습니다.

## 운영/개발 모드

기본은 live입니다. URL 미설정 시 '날씨 서버 연결 설정이 필요합니다'를 표시하고 기온을 만들지 않습니다.
자료가 없을 때의 흐림 이미지는 시각적 fallback이며 실제 날씨가 흐리다는 뜻이 아닙니다.

`weather-schedule-app/.env.example`을 같은 폴더의 `.env.local`로 복사하면 됩니다. 기존 `.env.local`이 있으면 덮어쓰지 말고 아래 공개 설정만 확인하세요. `.env.local`은 계속 Git에서 제외됩니다.

```dotenv
EXPO_PUBLIC_WEATHER_API_URL=https://<TEAM_WORKER>.<TEAM_SUBDOMAIN>.workers.dev/weather
EXPO_PUBLIC_WEATHER_MODE=live
```

`demo`는 `__DEV__`일 때만 작동합니다. 릴리스 빌드에서는 demo 환경변수도 무시하고 live를 사용합니다.
데모 모드는 출처 영역에 '개발용 테스트 날씨 · 실제 기상청 조회 아님'을 명시합니다.
기존 일정 카드 2개는 이번 작업 범위 밖의 고정 UI 데이터이며 실제 사용자 일정으로 연결하지 않았습니다.
환경변수를 바꾸면 Metro 서버를 재시작해야 합니다. 앱에는 공개 서버 주소만 설정하며 실제 인증키는 복사하거나 저장하지 않습니다.
8초 디자인 테스트를 명시적으로 사용할 때만 로컬 설정의 모드를 `demo`로 바꾸세요.

## Codespaces 미리보기 주소와 CORS

Codespace를 새로 만들거나 포트를 바꾸면 미리보기 Origin도 바뀔 수 있습니다.
브라우저 주소에서 경로·쿼리·마지막 `/`를 제외한 `https://호스트` 부분을 확인하세요.
Codespaces를 쓰는 경우 해당 미리보기의 정확한 origin을 환경별 배포 입력으로 전달합니다.

주소가 달라지거나 CORS 403이 발생하면 실제 배포의 `ALLOWED_ORIGINS`를 확인합니다.
로컬 기본값은 `server/wrangler.jsonc`에 있으며, 배포할 때 필요한 origin을 쉼표로 구분해 지정합니다.
`*` 또는 모든 `app.github.dev` 주소를 허용하지 말고, 더 이상 사용하지 않는 Origin은 검토 후 제거하세요.
실제 서버 허용 목록은 승인된 배포 이후에 반영됩니다. 대시보드에서만 바꾼 값은 다음 Wrangler 배포에서 설정 파일 값으로 덮어써질 수 있습니다.
이번 안내 정리에서는 서버 허용 목록이나 Cloudflare 설정을 변경하지 않았습니다.

## 위치

운영 서버 URL이 설정된 경우에만 전경 위치 권한을 요청합니다. 키/서버 준비 전에는 불필요하게 위치를 수집하지 않습니다.
권한 거부·GPS 오류·10초 시간 초과·국외 좌표는 서울(60,127)로 대체하며 출처 영역에 이유를 표시합니다.
시작 시 한 번 현재 위치를 확인합니다. 이동 후 다른 격자 날씨를 원하면 앱을 재시작해야 합니다.
전경의 대략적 위치만 사용하며 백그라운드 위치/지속 추적은 사용하지 않습니다.
서버에는 원시 위경도가 아닌 격자만 보내고 앱 캐시에도 원시 위경도를 저장하지 않습니다.
웹 위치 권한은 HTTPS 또는 localhost 보안 컨텍스트가 필요합니다.
Android 권한은 expo-location 플러그인으로 준비했습니다. 실제 기기 권한 흐름은 아직 미검증이며 네이티브 빌드를 새로 생성해야 할 수 있습니다.

## 발표 시각·캐시·실패

- 시간 계산은 실행 서버/기기 시간대와 무관하게 KST(UTC+9)로 합니다.
- 실황 HH:00, 초단기예보 HH:30을 기준으로, 발표 후 15분의 보수적인 제공 유예를 둡니다.
- 예: KST 10:44는 09:30 예보, 10:45부터 10:30 예보를 요청합니다. 자정 이전 날짜도 계산합니다.
- 최신 주기의 제공 실패는 한 번 이전 시간 주기로 재시도합니다. 한 격자 갱신은 보통 2회, 최대 4회 기상청 호출입니다.
- 관측 2시간 초과/미래 관측/기본 필드 누락/결측 sentinel/범위를 벗어난 기온은 정상 자료로 저장하지 않습니다.
- 예보는 현재에 가장 가까운 시각을 선택하며, 과거 30분~미래 90분 범위 안의 동일 시각 SKY/PTY/LGT만 묶습니다.
- 서버 격자별 5분 캐시, 동시 요청 병합, Durable Object 저장소에서 전역 일일 호출 예산을 원자적으로 예약합니다.
- KST 일일 기본 800회(실제 발급된 활용 한도에 맞춰 조정), IP 해시별 분당 20요청. 예산 초과는 추가 호출 없이 중단합니다.
- 서버 IP는 해시 후 단기 제한 카운터에만 사용하며 응답/로그에 출력하지 않습니다. 이전 캐시 항목은 정기 alarm에서 정리합니다.
- 앱은 15분 갱신, 실패 시 1→2→4→8→15분 재시도, 백그라운드 자동 조회 중지, 5분 이상 경과 후 전경 복귀 시 조회합니다.
- 서버 오류 시 6시간 이내 마지막 관측을 stale로 반환할 수 있습니다. 앱도 격자별 AsyncStorage의 마지막 정상 데이터만 복원합니다.
- 관측 90분 초과/예보 유효 시각 1시간 경과/응답 15분 초과/오류/로컬 복원 상태는 오래된 자료로 안내합니다.
- 마지막 관측이 6시간을 넘으면 기온을 숨기고 유효시간 만료를 표시합니다. 마지막 자료가 없는 오류에는 기온이 표시되지 않습니다.

## 인증키 발급 후 필요한 설정 (이번 작업에서는 실행하지 않음)

1. 공공데이터포털에서 **기상청 단기예보 조회서비스** 활용 신청·승인 후 키와 한도를 확인합니다.
2. Cloudflare 계정의 Workers/Durable Objects 지원·요금/한도와 대상 리전을 검토합니다.
3. `server/wrangler.jsonc`의 ALLOWED_ORIGINS에 정확한 웹 origin(스킴·호스트·포트)을 등록하고 DAILY_UPSTREAM_LIMIT를 발급 한도보다 낮게 맞춥니다.
4. 서버 secret 저장소에만 키를 등록합니다. 다음은 향후 설정 명령 예시이며 이번 작업에서 실행하지 않았습니다.

```sh
npx wrangler secret put KMA_SERVICE_KEY --config server/wrangler.jsonc
```

프롬프트에는 디코딩 키를 권장합니다. 인코딩 키는 서버가 한 번만 디코딩한 뒤 URLSearchParams로 전달합니다.
키를 `EXPO_PUBLIC_*`, app.json, 소스 코드, GitHub, 브라우저 URL에 절대 넣지 않습니다.
`server/.dev.vars`를 로컬 서버 테스트에 쓸 수 있지만 해당 파일은 Git에서 제외됩니다.

5. 서버를 다시 구성할 때 원격 접근·예산·권한을 검토합니다. 현재 저장소는 `workers_dev: true`로 무료 기본 주소를 사용하도록 설정되어 있습니다. 이번 문서 정리에서는 배포하지 않았습니다.
팀 계정 배포 및 HTTPS 주소 설정은 [출시팀 설정 가이드](../../RELEASE_GUIDE.md)를 참고합니다.
6. 앱의 EXPO_PUBLIC_WEATHER_API_URL을 승인된 서버의 `/weather` 주소로 설정하고 개발 서버/빌드를 다시 만듭니다.
7. 서울 및 실제 기기에서 기온·격자·원시 관측/예보 시각·LGT와 홈 표시를 대조합니다. 실제 API 성공은 이 단계에서 따로 검증해야 합니다.

CORS는 브라우저 origin 제한이며 앱 인증 수단이 아닙니다. 네이티브 앱은 Origin 없이 요청할 수 있습니다.
현재 전역 예산·요청 제한으로 키를 보호하지만, 상용 배포 전 WAF/앱 무결성 검증 또는 인증된 게이트웨이로 악의적인 예산 소진을 추가 방어해야 합니다.
인증키가 URL 쿼리에 필요한 기상청 특성상 중계 서버의 fetch URL/요청 로그/오류 추적 도구에서 serviceKey가 기록되지 않도록 해야 합니다.
이번 코드에는 해당 URL·키를 출력하는 로그가 없고 Worker observability도 꺼 두었습니다.
