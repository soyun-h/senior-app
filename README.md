# 개인 프로젝트 회고록

*개인 프로젝트 회고록 | 6~12주차*

**프로젝트:** 노년층 AI 아바타 기반 일정 관리 서비스 (all it)

**기록 기간:** 6~12주차

**주요 담당 영역:** UX 리서치, 서비스 기획, UI·비주얼 디자인, 개발 협업 및 QA

이 회고록은 사용자 리서치와 서비스 기획, 디자인 제작 및 검수, 개발 협업 과정에서 제가 맡은 업무를 중심으로 정리한 기록입니다. 직접 수행한 조사·기획·디자인·실행 화면 검수와 GitHub·Codex를 활용한 개발 협업을 구분했습니다. 팀원들과 함께 논의하거나 제작한 결과는 공동 작업으로, 개선을 제안한 내용은 논의 및 검토 단계로 기록했습니다.

### 6주차 | 사용자 테스트 및 개선 방향 논의

#### 1. 노년층 대상 사용자 테스트 진행

효창공원과 종로 일대를 중심으로 테스트 참여자를 모색하고, 노년층을 대상으로 사용자 테스트를 진행했습니다. 기존에 제작한 프로토타입을 직접 사용해 보도록 하면서, 어느 부분에서 어려움을 느끼는지와 어떤 기능을 아쉬워하는지를 중심으로 관찰했습니다.

사용 과정에서는 직접적인 개입을 최대한 줄이려고 했습니다. 다만 일정 시간이 지나도 다음 단계로 이동하지 못하는 경우에는 간접적인 개입으로 진행을 유도했습니다. 사용자가 스스로 화면과 기능을 이해하는 과정, 도움이 필요한 지점을 살펴보는 데 집중했습니다.

#### 2. 테스트 결과 템플릿 작성 및 팀 내 공유

사용자 테스트 결과를 바탕으로 템플릿을 작성했습니다. 이후 팀원들과 비대면 회의를 진행하며 각자가 확인한 결과를 공유했습니다. 제 관찰 결과만으로 방향을 결정하기보다, 팀원들이 수집한 결과와 함께 다음 작업의 근거로 정리했습니다.

#### 3. 추후 개선 방향 논의

테스트 결과를 바탕으로 팀원들과 다음 개선 방향을 논의했습니다.

- 글자 크기를 조정하는 방향
- 아이콘과 버튼이 무엇을 의미하는지 명확히 전달하는 방법
- 애니메이션 형식의 동작 방식을 적용하거나 검토하는 방향

이 주차에서는 문제를 관찰하고 개선 방향을 논의하는 데 중점을 두었으며, 논의한 항목을 추후 개선 방향으로 정리했습니다.

### 7주차 | 중간 발표 및 디자인 시안 개발

#### 1. 중간 발표 자료와 서비스 방향 변경 근거 정리

프로젝트 진행 중 서비스의 방향성이 여러 차례 변경됐기 때문에, 그동안의 자료와 흐름이 바뀐 근거를 모아 정리했습니다. 단순히 최종 화면만 보여주기보다 방향을 수정한 이유와 진행 과정을 설명할 수 있도록 자료를 준비했습니다.

팀원들과 진행 과정을 어떻게 제시할지 논의하고, 이를 바탕으로 중간 발표의 흐름을 구체화했습니다.

#### 2. 시안 B 앱 화면 디자인

기존 와이어프레임과 다른 디자인 방향을 탐색하기 위해 시안 B의 아이디어를 정리하고 앱 화면을 디자인했습니다. 시안 A와 구분되는 구성은 다음과 같았습니다.

- **우측 하단 플로팅 액션 버튼:** 버튼을 선택하면 설정·캘린더·문서 등의 세부 기능 아이콘이 수직으로 펼쳐지는 구조를 구성했습니다.
- **아바타 상단의 고정 텍스트:** 화면 상단 우측, 아바타 위쪽에 텍스트를 고정해 자연스럽게 시선을 유도하는 방향을 잡았습니다.
- **하단 입력 방식의 차별화:** 하단 중앙의 별도 음성인식 버튼 대신 텍스트 입력과 저장을 위한 버튼 형태를 제시했습니다.

시안별 화면 구성과 조작 방식의 차이를 검토하는 디자인 단계의 작업이었습니다.

#### 3. 중간 발표 PPT 공동 제작 및 최종 수정

팀원들과 중간 발표 PPT의 전체 흐름을 정리한 뒤 백피 작업을 진행했고, PPT의 색감과 전반적인 디자인 과정에도 함께 참여했습니다.

PPT를 완성한 이후 여러 수정점을 발견해 마지막 수정 작업을 맡았습니다. 발표 흐름을 정리하는 과정과 시각적 표현을 보완하는 과정을 팀원들과 함께 진행했습니다.

#### 4. 중간 발표 진행

중간 발표에서 후반부 설명을 맡았습니다. 와이어프레임과 프로토타입 작업 이후의 과정, 최종 퍼소나 선정, 전반적인 디자인 시안 결과를 설명했습니다. 앞서 정리한 자료를 바탕으로 디자인 결과가 나오기까지의 작업 흐름을 전달했습니다.

### 8주차 | 사용자 테스트 기반 서비스 방향 재정립

#### 1. 경로당 재방문 및 4차 사용자 테스트 진행

프로토타입을 발전시키는 과정에서 정보 제공 방식과 화면 구성에 관한 문제를 발견했습니다. 이를 확인하고 개선 방향을 찾기 위해 경로당을 재방문해 4차 사용자 테스트를 진행했습니다.

테스트를 바탕으로 기존 서비스의 기능 구성과 정보 전달 방식을 다시 검토했습니다. 특히 노년층 사용자가 서비스를 이용할 때 무엇이 중요한지 재판단하는 계기로 삼았습니다.

#### 2. 서비스 핵심 기능 재정의 제안

기존 서비스에는 일정 관리 외에도 일기 작성과 일기 공유 등의 부가 기능이 포함돼 있었습니다. 사용자 테스트 이후 서비스의 목적을 더 명확하게 하기 위해 다음 방향 수정을 제안했습니다.

- 일기 작성 및 일기 공유 기능 제외
- 일정 관리 기능을 서비스의 중심 기능으로 강화
- AI 아바타가 제공할 정보의 방향과 역할 재검토
- 사용자가 일정을 확인하고 관리하는 과정에 집중하도록 서비스 구조 변경

여러 기능을 제공하는 것보다 핵심 문제를 명확하게 해결하는 서비스로 범위를 좁히는 데 초점을 맞췄습니다. 기능을 추가하는 것뿐 아니라, 서비스의 목적에 맞춰 무엇을 덜어낼지도 함께 고민했습니다.

#### 3. 정보 위계와 화면 구성 정리 및 피드백 요청

변경된 서비스 방향에 맞춰 기능 간 중요도와 화면 구성의 위계를 다시 정리했습니다. 서비스 구조를 Figma에 정리한 뒤 교수님께 공유하고 피드백을 요청드렸습니다. 방향 변경의 내용을 화면과 구조로 전달하는 작업을 맡았습니다.

### 9주차 | 피드백 반영 및 브랜드 아이덴티티 개발

#### 1. 중간 발표 피드백 공유 및 서비스 방향 논의

중간 발표 피드백을 전달받고 팀원들과 앞으로 서비스에 반영할 사항을 논의했습니다. 당시 논의한 주요 항목은 다음과 같습니다.

- 음성 버튼을 없애는 방향
- 아바타와 캐릭터에 대한 수요 조사 필요성
- 사용자를 돕기 위한 서비스의 의도와 의존성에 대한 우려를 어떻게 함께 검토할지에 관한 문제
- 당시 하단바의 일정·추억일기·홈 위치가 계속 바뀌는 문제
- 체크 표시와 알람 페이지를 구분하고, 오늘 해낸 일을 더 명확하게 보여줄 필요성
- 투명 배경을 제외하는 방향
- 사용자가 알림이나 전화를 거부했을 때의 흐름
- 알림에 따른 행동이 반복적으로 수행되지 않을 때 보호자에게 알리는 기능을 고려하는 방향

위 항목은 피드백을 바탕으로 서비스에 반영할 필요성과 흐름을 논의한 내용입니다. 아바타·캐릭터 수요 조사와 보호자 알림 역시 당시의 검토 과제로 다뤘습니다.

#### 2. 피드백을 반영한 와이어프레임 수정

제공받은 피드백과 변경된 서비스 흐름을 바탕으로 와이어프레임을 수정했습니다. 기존 두 시안 중 한 가지를 선택하고, 당시 검토용 화면에서는 하단 네비게이션바를 제거한 버전을 구성했습니다.

이 작업은 해당 시점의 화면 구성을 검토하기 위한 디자인 수정으로, 이후 최종 구현 단계의 화면 구성과 구분해 기록했습니다.

#### 3. all it 로고 디자인 보강 및 그리드 적용

제가 팀원들에게 제안한 로고 시안이 선택됐고, 이후 역할 분담을 통해 all it 서비스의 로고 디자인 보강을 맡았습니다.

서비스명과 체크 아이콘을 결합한 로고를 다양한 컬러와 구조로 해체하고 다시 결합하면서 최종 디자인을 도출했습니다. 이후 로고의 그리드를 정리하고 와이어프레임에 일괄 적용했습니다. 팀 내 시안 선택과 역할 분담을 바탕으로 브랜드의 시각적 표현을 구체화한 작업이었습니다.

### 10주차 | AI 아바타 및 홈 화면 디자인·개발

#### 1. AI 아바타 캐릭터 비주얼 제작

노년층 일정 관리 앱의 홈 화면에서 사용할 AI 아바타 이미지를 ChatGPT 이미지 생성 기능을 활용해 제작했습니다.

아바타가 영상통화 형식으로 사용자와 소통한다는 서비스 특성을 고려해, 실제 인물과 대화하는 듯한 시각적 인상을 주고자 했습니다. 이 활동은 아바타의 비주얼 제작에 관한 것으로, 실제 영상통화 기능을 구현한 작업과는 구분됩니다.

#### 2. 날씨별 홈 화면 배경 이미지 제작

사용자가 현재 날씨를 시각적으로 인지할 수 있도록 맑음·흐림·비·눈·번개 상태별 배경 이미지를 각각 제작했습니다.

각 이미지가 하나의 서비스 안에서 자연스럽게 이어지도록 전체적인 이미지 스타일을 조정했습니다. 날씨 상태를 구분하는 동시에 홈 화면의 시각적 일관성을 유지하는 방향으로 작업했습니다.

#### 3. 홈 화면 주요 UI 디자인 수정

홈 화면의 아바타, 대화창, 날씨 배경 등 주요 UI 요소의 디자인 수정을 맡았습니다. 홈 화면을 구성하는 요소들의 관계를 정리하고, 이후 개발 과정에서 비교할 디자인 기준을 마련했습니다.

#### 4. React Native·Expo 개발 환경 구축 협업

기존 디자인을 실제 모바일 앱으로 구현하기 위해 GitHub와 Codex를 활용해 React Native·Expo 기반 프로젝트 생성과 코드 업로드를 진행했습니다. 작업은 `허소윤/members` 브랜치를 중심으로 관리했습니다.

초기 개발 범위는 홈 화면 구현을 우선하도록 설정했습니다. 이 과정에서 저는 개발 범위와 구현 기준을 정하고, Codex를 활용한 프로젝트 구성 및 구현 결과를 확인하는 개발 협업 역할을 수행했습니다.

#### 5. Figma 시안 전달 및 홈 화면 구현 결과 검수

Figma에서 제작한 홈 화면 디자인을 개발 과정에 전달하고, 구현된 화면이 시안과 일치하도록 검수했습니다. 디자인 파일에 직접 접근하기 어려운 문제가 있어 원본 이미지와 아이콘 에셋을 ZIP 형태로 전달했습니다.

홈 화면의 요소를 개별 컴포넌트로 분리하는 방향으로 Codex와 개발을 진행하면서 다음 항목의 구성과 위치를 확인했습니다.

- 날씨 배경
- 아바타
- 날씨 안내 문구
- 일정 카드
- 하단 네비게이션

디자인을 전달하는 데서 끝내지 않고, 원본 에셋과 화면 구성 의도가 구현 결과에 유지되는지 확인했습니다.

#### 6. 날씨 배경 전환 기능의 초기 개발 방향 설정

실시간 날씨 정보를 홈 화면 배경에 반영하는 기능을 우선 구현 대상으로 선정했습니다. 초기에는 테스트 데이터로 날씨 상태별 배경이 전환되도록 개발하고, 이후 실제 기상청 API와 연동할 수 있는 구조를 마련하는 방향을 설정했습니다.

이 단계에서는 테스트용 데이터에 의한 전환과 실제 API 연동을 구분했습니다. 초기 테스트 배경 전환을 실제 날씨 조회 성공으로 혼동하지 않도록 개발 범위를 정리했습니다.

### 11주차 | UI 정밀 보정 및 일정 관리 기능 개발

#### 1. 홈 화면 디자인 정밀 비교 및 보정 검수

실제 구현된 홈 화면과 Figma 최종 완성 시안을 비교하며 차이를 확인하고, 세부 디자인을 보정하는 작업을 진행했습니다. 주요 검수 항목은 다음과 같습니다.

- 날씨별 배경 이미지의 명도와 대비
- 아바타의 크기와 화면 내 위치
- SVG 아이콘의 형태와 원본 비율
- 홈 버튼의 디자인 디테일
- 일정 카드의 글래스모피즘 표현
- 반투명 카드의 블러·테두리·하이라이트

기능이 작동하는지만 확인하는 데 그치지 않고, 구현 화면이 디자인 시안의 시각적 완성도를 유지하는지 검수했습니다. 제가 발견한 차이와 수정 기준을 개발 과정에 전달하고 결과를 확인하는 역할을 수행했습니다.

#### 2. 모바일 실행 환경 및 화면 검수 방식 점검

Expo Go를 이용한 iOS 실행 방법과 웹 미리보기 환경을 확인했습니다. 로컬 개발 환경을 직접 구성하기 어려운 상황을 고려해, 웹 미리보기와 PNG 화면 캡처를 활용하는 방식으로 구현 결과를 검토했습니다.

GitHub 브랜치, Expo Go 테스트, 웹 미리보기 각각의 환경에서 코드가 어떻게 반영되는지도 확인했습니다. 검수 환경에 따라 확인할 수 있는 범위가 다르다는 점을 살펴보며 작업을 진행했습니다.

#### 3. 노년층 서비스 접근성 점검 가이드 작성

노년층 사용자를 고려해 주요 기능과 화면 구성에 접근성 기준을 적용할 때 검토해야 할 요소를 정리했습니다. 그중 처방전 AI 인식 기능의 위험성을 별도로 살펴봤습니다.

AI가 복약 정보를 잘못 인식하면 사용자의 건강에 직접 영향을 줄 수 있으므로 오류의 심각도를 높게 평가했고, 실제 구현 과정에서는 해당 기능을 생략할 것을 제안했습니다. 또한 WCAG 3.3.4의 적용 여부는 기능의 성격과 입력·제출 맥락에 따라 판단해야 한다는 점을 확인했습니다. 작성한 접근성 문서는 GitHub의 `허소윤/members` 브랜치에 업로드하고 개발 코드와 분리해 관리했습니다.

#### 4. 일정 관리 UI·UX 구체화 및 화면 디자인 수정

##### 4-1. 기능 정의와 사용자 흐름 구체화

일정 목록과 등록 화면을 실제로 구현하기 위해 기능을 정의하고 디자인 검수를 진행했습니다. 등록 과정에서 날짜, 반복 요일, 시간, 알림 방식 등을 선택할 수 있도록 화면과 인터랙션을 구체화했습니다.

기능 정의 및 검수 범위로 정리한 항목은 다음과 같습니다.

- 단일 날짜 선택과 반복 요일 설정
- 달력에서 기간을 드래그해 선택하는 기능
- 오전·오후, 시·분을 선택하는 시간 휠
- 영상통화·일반 알람·알림 없음 선택
- 일정 등록 후 목록으로 이동하는 흐름
- 일정 완료 체크와 완료 상태 저장
- 일정 삭제 확인
- 오늘 날짜에 해당하는 일정만 목록에 표시하는 기준
- 홈 화면과 실제 일정 데이터 연동

##### 4-2. 변경된 흐름을 반영한 화면 디자인

보강한 사용자 흐름을 바탕으로 일정 선택 과정에서 제공되는 모든 화면의 전면 디자인 수정 작업을 맡았습니다. 기능을 정의하는 작업과 실제 화면을 디자인하는 작업을 함께 진행하고, 구현 과정에서는 Codex를 활용해 해당 기준이 반영되는지 확인했습니다.

#### 5. 인터랙션 및 애니메이션 정의와 개발 검수

일정 관리 화면이 정적인 정보 표시에 머무르지 않도록 사용자 피드백 요소를 구체화했습니다. 일정 등록 완료 후 나타나는 토스트 메시지의 표시 방식과 애니메이션을 정의했습니다.

알림 방식 선택 영역에는 Stretch & Snap 형태의 인터랙션을 적용하도록 요청하고, 선택 상태가 바뀔 때의 시각적 움직임을 검토했습니다. 일정 데이터를 불러오는 과정에서는 Shimmer 스켈레톤을 사용하는 방향으로 Codex와 개발을 진행했습니다.

Codex에 필요한 피드백과 움직임을 설명하고, 구현된 인터랙션이 의도한 방식으로 표현되는지 검수하는 역할을 맡았습니다.

#### 6. 기능 구현 범위와 기존 디자인의 분리 관리

일정 기능을 개발하면서 기존 홈 화면, 날씨 API, 아바타, 하단 네비게이션이 변경되지 않도록 수정 범위를 구분했습니다. Codex에 필요한 수정 사항과 보호해야 할 기존 요소를 구체적으로 전달했습니다.

새로운 기능을 반영하는 과정에서도 기존 디자인이 손상되지 않도록, 변경 대상과 유지 대상을 분리해 개발 협업과 검수를 진행했습니다.

### 12주차 | 실기기 QA 및 코드 통합, 사용성 개선 검토

#### 1. 실제 Expo Go 화면과 원본 디자인 비교 검수

Expo Go에서 실행한 일정 목록과 원본 Figma 시안을 비교하면서 카드 배경 프레임의 크기와 알림 토글의 배치가 다르게 보이는 문제를 발견했습니다.

처음에는 토글 크기 문제로 해석됐지만, 실제로는 카드 배경 프레임의 크기와 비율이 원본 디자인과 맞지 않는 문제임을 구분했습니다. 이에 따라 내부 요소를 다시 조정하기보다 배경 프레임을 확인하는 방향으로 수정 요청을 재설정했습니다.

#### 2. 영상통화 알림 ON/OFF 오류 발견 및 수정 결과 검수

알림 없이 등록한 일정의 토글을 ON으로 바꿔도 카드의 활성 상태와 알림 설정이 변경되지 않는 문제를 발견했습니다. 목록의 토글이 영상통화 알림을 제어하는 용도라는 점을 명확히 정의하고 다음 수정 사항을 요청했습니다.

- **ON:** 영상통화 알림으로 저장하고 활성 카드 표시
- **OFF:** 알림 없음으로 저장하고 비활성 카드 표시
- 설정값을 저장해 앱 재실행 후에도 상태 유지
- 완료 체크와 반복 일정 설정은 알림 상태와 별도로 유지

기존 일반 알람 데이터가 임의로 변경되지 않도록 처리 조건도 검토했습니다. 저는 기능의 의미와 기대 동작을 정리하고, Codex를 통한 수정 결과를 검수했습니다. 이 작업은 알림 선택 상태와 저장·표시의 연동에 관한 것으로, 실제 영상통화나 알림 발송 기능을 새로 구현한 작업과는 구분됩니다.

#### 3. 삭제 완료 토스트 애니메이션 통일 요청

일정 등록과 삭제의 피드백 표현이 일관되지 않은 문제를 발견했습니다. 등록 완료 토스트와 같은 방식으로 삭제 완료 토스트에도 opacity 애니메이션을 적용하도록 요청했습니다.

- 250ms 페이드인
- 1,600ms 유지
- 600ms 페이드아웃

기존 토스트의 디자인과 위치는 유지하고 등장·퇴장 효과만 바꾸도록 수정 범위를 제한했습니다. 구현은 Codex와 협업해 진행하고, 동일한 피드백 방식이 적용되는지 확인했습니다.

#### 4. 카드 배경 렌더링 오류 발견 및 원인 진단 과정 검수

기능 수정 이후 실제 Expo Go에서 일정 카드의 초록색·흰색 배경 프레임이 사라지는 문제를 발견했습니다. 개발 결과를 반복해서 검수하면서, 원본과 비슷한 배경을 새로 만드는 대신 기존 에셋의 렌더링 원인을 조사하도록 방향을 제시했습니다.

이후 Codex에서 네이티브 진단 로그를 추가했고, 저는 Codespaces와 Expo Go를 연결해 실제 실행 로그를 확인했습니다. 진단 과정에서는 다음 항목을 확인했습니다.

- 카드와 이미지의 레이아웃 크기
- PNG 소스 해석 결과
- 이미지 로딩 성공 여부

최종적으로 실제 iOS Expo Go에서 카드 배경과 알림 ON/OFF에 따른 프레임 전환이 정상적으로 표시되는 것을 확인했습니다. 웹 화면 확인만으로 마무리하지 않고 실기기 결과를 확인하는 검수 과정을 진행했습니다.

#### 5. 임시 진단 코드 정리 및 최종 검수

문제 확인을 위해 추가했던 개발용 진단 로그를 제거하도록 요청했습니다. 진단 코드 제거 후에도 실제 화면이 동일하게 표시되는지 확인하며 검수를 마무리했습니다.

#### 6. 검수 브랜치 관리 및 작업 브랜치 통합

일정 기능을 개발하는 동안 `preview/schedules` 브랜치를 활용해 기존 작업 브랜치와 분리된 상태로 개발 및 검수를 진행했습니다.

실제 Expo Go에서 주요 기능을 확인한 뒤, 검수 결과를 작업 브랜치인 `허소윤/members`에 반영하는 절차를 진행했습니다. 최종적으로 일정 기능과 관련된 10개 커밋이 반영됐고, GitHub에서 두 브랜치의 코드가 동일한 상태임을 확인했습니다.

검사 실행 결과는 Codex 보고 기준으로 테스트 62개와 TypeScript 검사 통과를 확인했습니다. 개발 코드의 검사 실행과 결과는 Codex 보고를 통해 확인하고, 실제 iOS Expo Go에서는 주요 화면과 기능을 직접 검수했습니다.

#### 7. 일정 목록의 사용성 문제와 다음 개선 방향 검토

일정 목록 UI에 대한 피드백을 바탕으로 기존 인터랙션의 사용성 문제를 검토했습니다. 확인한 문제는 다음과 같습니다.

- 카드 색상이 알림 ON/OFF를 의미한다는 점이 직관적으로 전달되지 않음
- 체크 표시만으로 일정 완료 여부를 인식하기 어려움
- 완료한 일정이라는 시각적 표현이 부족함
- 카드를 짧게 눌러도 동작이 없어 일정 수정 기능을 찾기 어려움
- 알림을 ON으로 바꿨을 때 영상통화와 일반 알람 중 어떤 방식인지 명확하지 않음

이를 바탕으로 카드의 정보 위계와 인터랙션을 개선하는 방향을 검토했습니다. 다음 제안을 논의했습니다.

- 완료 일정에 취소선과 완료 문구 표시
- 알림 상태와 카드 배경색의 표현 분리
- 알림 방식 선택 UI
- 카드 탭 시 일정 수정 화면으로 이동

위 항목은 사용성 개선을 위한 검토·논의 내용이며, 구현 완료한 기능으로 기록하지 않았습니다. 실기기에서 기능이 정상 작동하는지 확인한 이후에도, 사용자가 각 상태와 조작의 의미를 이해하기 쉬운지 검토하는 것이 다음 개선 과제로 남았습니다.
